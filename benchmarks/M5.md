Notes:
- **Reference-only files not reused.** README.md / PROGRESS.md / RESUME_BULLETS.md numbers were not copied; every value above was freshly measured on this M5 this session.
- **Fresh noise realization per run.** `evaluate_enhancement.py` draws random noise each run at fixed SNR levels (0/5/10 dB), so the noisy/enhanced WER values are not a strict A/B against any other machine — only the SNR levels are held fixed. (This run's noisy WER was 35.7/14.3/3.6% vs a prior M5 draw of 25.0/3.6/3.6%, illustrating the per-run noise variance.)
- **On the M5, enhancement did not improve WER at any level this run.** Enhanced WER was worse than noisy at both 0 dB (42.9 vs 35.7%) and 5 dB (28.6 vs 14.3%) and tied at 10 dB (3.6%). Signal-level SNR gain was positive at every level (+12.1 / +9.5 / +7.3 dB), so this is the well-documented case where an SNR improvement does not translate to an ASR improvement — the on-device recognizer is already robust to this noise. Enhancement's demonstrated value on the M5 is the SNR gain and the real-time latency (13 ms/chunk), not WER reduction.
- **Object detection F1 = 0 is expected.** The synthetic `--vision-eval` images carry no labeled COCO objects (text-only signs/labels); the desk scene produced false-positive LAPTOP/MUG detections against an empty expected set. OCR is the meaningful vision-eval metric here.
- **Synthetic sound set caveat.** The 6 `--sound-eval` clips are macOS-TTS/synthesis generated and don't match the classifier's real-world training distribution; F1 is dominated by which synthetic clips land near a class boundary. Live `--multimodal` is the meaningful real-world check.
- **Fairness n=1 per group.** Kruskal-Wallis is not significant (p = 0.4159) because there is one utterance per accent; the disparity is driven by the Fred (US_male) robotic-TTS outlier. Enhancement targets noise, not voice quality, yet the mitigated pass still narrowed the accent disparity from 25.0 → 17.9 pp on this run. Lighting recall is already saturated at 100%, so Wilcoxon W=0, p=1.0.
- **Live runs (`--measure`, `--vision`, `--multimodal`) were completed by a human** — no TBDs remain.
- **Live spoken WER varies with read completeness, not the recognizer.** Three `--measure` runs scored 14.3% / 57.1% / 96.4%. The 96.4% run captured only "Monday and Thursday" (the reader did not read the reference); the 57.1% run trailed off mid-sentence ("…the world smaller"); the 14.3% run is the one complete read and is the representative live number. Caption latency was stable across all three runs (mean 5.4–6.8 s), since it is bound by the recognizer's finalization cadence and speaking pace, not compute — and is far higher than the 3.6% file-based clean WER because of live mic/room acoustics and the 30 s capture window clipping the sentence tail. On-device recognition confirmed (`requiresOnDeviceRecognition = true`).
- **Live vision matches the file-based latency story.** 29.4 FPS at 40 ms avg over a 91.8 s session (242 processed frames) on the full YOLOv8n + OCR pipeline; the live OCR mis-reads (e.g. "ComIx", "IntornatknMI") are expected from a hand-held camera on non-frontal text and do not affect the FPS/latency measurement.
- **Multimodal fusion fired end-to-end.** SoundAnalysis events (finger snapping 100%, speech, door) were fused in real time with the Vision context ("I see person"/"I see clock") at 23 ms mean latency, fully on-device.
